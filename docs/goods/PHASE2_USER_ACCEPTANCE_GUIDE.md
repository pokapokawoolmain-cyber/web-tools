# PHASE 2 USER ACCEPTANCE GUIDE — 共有（Shared Catalog / Personal Collection）

対象: CEO（Acceptance 担当）
目的: 「誰かが作ったグッズリストを共有し、各自が自分だけのコレクションとして使える」こと、そして**自分の取得状況が他人に漏れない**ことを、2人分のアカウントで確認していただく。

> ローカル専用の環境です。本番の Supabase・本番ドメイン・本番データには接続していません。
> 起動方法・ログイン方法の詳細は `PHASE1_USER_ACCEPTANCE_GUIDE.md` §1〜§2 と同じです（Phase 1 ガイドの「C3 共有は未実装」は本 Phase で解消）。

---

## 0. 準備

### 0-1. 起動（Mac のターミナル。すでに起動していれば不要）
```bash
cd ~/web-tools-goods
PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH" supabase start --workdir supabase-goods
```
```bash
npm run goods:seed-acceptance
```
```bash
npm run goods:acceptance -- --lan
```

### 0-2. 2人分の画面を用意する
共有は「作った人（A）」と「受け取った人（B）」の2人で確認します。**同じブラウザの同じウィンドウでは2人同時にログインできない**ため、次のどれかで分けてください。

| 方法 | A（作った人） | B（受け取った人） |
|---|---|---|
| おすすめ | スマホ | Mac のブラウザ |
| Mac だけで | 通常ウィンドウ | シークレット（プライベート）ウィンドウ |

| 役 | アカウント | 初期状態 |
|---|---|---|
| **A** | `ceo-acceptance@example.test` | Sample Live 2026 など3イベントを持っている |
| **B** | `ceo-friend@example.test` | イベントなし |

- URL: Mac `http://localhost:3300/goods`／スマホ `http://192.168.68.54:3300/goods`（Mac の IP が変わったら起動時の表示に従う）
- ログインコードは Mac で **Mailpit（http://127.0.0.1:55324）** を開いて、宛先が A / B どちらのメールかを確認して入力
- 最初からやり直すときは `npm run goods:seed-acceptance`（両方のアカウントが初期状態に戻ります。ログインし直してください）

## 2. 見ていただきたい観点
| 観点 | 確認 |
|---|---|
| 共有シートが分かりやすいか（スマホ片手で、作成→コピーまで迷わないか） | □ |
| 「取得状況は共有されない」ことが伝わり、安心して共有できるか | □ |
| 受け取った人が、ログイン → 追加までを迷わず進めるか（共有ページを見失わないか） | □ |
| 共有ページが通常のイベント画面と同じアプリに見えるか / 商品を短時間で把握できるか | □ |
| エラー表示（共有終了・期限切れ・利用不可）が自然な日本語か、内部情報（ID 等）が出ていないか | □ |

## 3. 既知の制約
| # | 内容 |
|---|---|
| C1 | 共有後の商品追加・編集は**再読み込みで反映**（自動で画面が更新される機能はない） |
| C2 | 1イベントにつき有効な共有リンクは1本。新しく作ると前のリンクは停止される |
| C3 | 有効期限は「期限なし / 7日間 / 30日間」のみ。発行後の延長はできない（作り直し） |
| C4 | 共有ページを開いてから1時間以上経つと「共有されたURLをもう一度開いてください」になる（安全のため） |
| C5 | Acceptance 環境は http のため、共有シートの「送る」（OS の共有機能）は表示されない。「コピー」を使う |
| C6 | メール内のログインリンクは使えない。6桁コードを使う |
| C7 | イベントの作成者は、誰が自分のリストを追加したか・その人の取得状況を見ることはできない（仕様） |

## 4. 未確認事項（Claude 側で確認できていないもの）
- iPhone Safari・Android Chrome の実機での共有操作（コピー・LINE等への貼り付け・受け取り側でのログイン）
- 本番環境で GA4 / Vercel Analytics に共有トークンが記録されないこと（構造上は記録されない設計。本番で要確認）
- Google ログイン経由での「自分の管理に追加」
- 別端末から LAN 経由での接続（同じ Mac からの確認のみ）
