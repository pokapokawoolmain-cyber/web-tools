# PHASE 1 USER ACCEPTANCE GUIDE — オタクグッズ管理（/goods）

対象: CEO（Acceptance 担当）
目的: スマートフォンで「イベントを作る → グッズを登録する → 一覧を眺める → 取得済みを切り替える → 進捗を確認する」が快適か、気持ちよく使えるかを判断していただく。

> この環境は **ローカル専用** です。本番の Supabase・本番ドメイン・本番データには一切つながっていません。ここで作ったデータは本番に混入しません。

---

## 1. Acceptance 環境へのアクセス方法

### 1-1. 起動（Mac のターミナルで実行）
すでに起動している場合は 1-2 へ進んでください。

```bash
cd ~/web-tools-goods
PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH" supabase start --workdir supabase-goods
```
```bash
npm run goods:seed-acceptance
```
```bash
npm run goods:acceptance -- --lan
```
- 1つ目: ローカルDB（Docker Desktop が起動している必要あり）
- 2つ目: テストデータを投入（何度実行しても初期状態に戻ります）
- 3つ目: Acceptance Preview を起動（本番ビルド。約1分）。表示された URL を使います
- スマホを使わない場合は `--lan` を付けずに `npm run goods:acceptance` でOK

### 1-2. 開く URL
| 端末 | URL |
|---|---|
| Mac のブラウザ | http://localhost:3300/goods |
| スマホ（Mac と同じ Wi‑Fi） | 起動時に表示される `http://192.168.x.x:3300/goods`（2026-10-01 時点では `http://192.168.68.54:3300/goods`） |
| ログインコードの確認（Mailpit） | http://127.0.0.1:55324 （Mac のブラウザ） |

注意:
- スマホ用 URL は **自宅・社内など信頼できる Wi‑Fi でのみ** 使ってください（同じネットワークの他の端末からも見えます）。
- Mac の IP アドレスが変わったら 3つ目のコマンドを再実行してください。
- 初回接続時に macOS が「受信接続を許可しますか」と聞いた場合は許可してください（スマホから接続するため）。
- 終了するときはターミナルで `Ctrl+C`。テストが終わったら `supabase stop --workdir supabase-goods` でローカルDBも止めてください（後述「既知の制約」参照）。

## 2. ログイン方法
1. `/goods` を開き「無料ではじめる / ログイン」
2. メールアドレスに **`ceo-acceptance@example.test`** を入力 →「ログインコードを送る」
3. Mac で **Mailpit（http://127.0.0.1:55324）** を開き、最新の「ToolBox グッズ管理 ログインコード」メールの **6桁の数字** を確認
4. ログイン画面にコードを入力 →「ログイン」

- 実際のメールは送信されません（ローカルの Mailpit が受け取るだけです）
- メール内の「ログインする」リンクは Acceptance 環境（ポート3300）では使えません。**必ず6桁コードを使ってください**
- 別の新規アカウントで試したい場合は、`test1@example.test` など任意の `@example.test` アドレスで同じ手順でログインできます（初回は空の状態から始まります）

## 4. CEO が行う操作手順と 5. 期待結果

スマホで A→R の順に進めてください（P・Q は端末を変えて確認）。

| # | 操作 | 期待結果 |
|---|---|---|
| **A 初回アクセス** | ログアウト状態で `/goods` を開く | 「買えた・まだを、ひと目で。」の紹介画面と「無料ではじめる / ログイン」ボタン。ToolBox の通常ヘッダーの下に「グッズ管理」のバーがある |

| **C My Events** | マイイベントを見る | 3イベントがカード表示。各カードにカバー、日付、「5 / 17 取得」と%、進捗バー。コンプリート済みは「コンプリート！」。スマホでは右下に「＋」ボタン |
| **D イベント新規作成** | 右下「＋」→ 何も入力せず「作成してグッズを登録」→ イベント名と日付を入力して再度押す | 未入力時は「イベント名を入力してください」と赤字＋入力欄へ移動。入力後はグッズ登録画面へ（見出し「グッズを登録しましょう」） |
| **E イベント編集** | 作成したイベントを開き、右上の鉛筆ボタン → 名前や概要を変更して「保存する」 | 変更が反映され「イベントを更新しました」。※編集画面下部の「イベントを削除」は確認ダイアログが出ます |
| **F グッズ追加** | 「グッズ追加」→ 商品名・価格を入力 →「保存して続けて追加」を数回 → 最後に「保存して一覧へ」 | 「このイベントに N 件追加しました」と出て入力欄が空になり、続けて登録できる。カテゴリは前回の値が残る。価格は「３，５００円」のような全角・カンマ・円付きでも可。「たぶん」など文字は「価格は数字で入力してください」 |
| **G 画像追加** | グッズ登録/編集で「写真を選ぶ・撮る」→ カメラで撮影 or 写真を選択 | 「画像を最適化しています…」の後にプレビュー。保存後、一覧に表示される。大きな写真でも数秒以内 |
| **H 10商品以上の一覧** | 「Sample Live 2026」を開く | 上部にカバー・イベント名・日付・概要、進捗「5 / 17 取得・29%」。商品はスマホで2列、画像はすべて正方形でサイズが揃う。長い名前は2行で「…」、価格未定は灰色の「価格未定」、画像なしは「画像なし」表示 |
| **I 取得済みへ** | 未取得のカード（例: パーカー）を1回タップ | 確認なしで即座に「✓ 取得済み」バッジ＋ピンクの太枠に変わり、件数と%が増える。下に「『パーカー』を取得済みにしました ／ 元に戻す」 |
| **J 取得済み → 未取得** | 取得済みのカードをもう一度タップ。誤タップ想定で「元に戻す」も試す | 「未取得」表示に戻り件数が減る。「元に戻す」（約6秒表示）で直前の状態に戻る |
| **K「すべて」** | フィルター「すべて」 | 全17件（自分で追加した分を含む）。件数バッジが総数と一致 |
| **L「取得済み」** | フィルター「取得済み」 | 取得済みのカードだけが表示。この状態でカードをタップして未取得にしても、カードはすぐには消えない（フィルターを切り替えると消える） |
| **M「未取得」** | フィルター「未取得」 | 未取得のカードだけ。フィルターはイベントごとに記憶される |
| **N 取得数 / 総数** | I〜M の間、上部の数字を見る | 「◯ / 17 取得」がタップのたびに即時更新 |
| **O コンプリート率** | %表示とバー。「Sample コンプリート済み」も開く | %とバーが連動。全取得のイベントは「100%」とピンク色の「コンプリートおめでとうございます！」 |
| **P スマホ幅** | §6 のチェック | — |
| **Q PC幅** | Mac のブラウザで同じ操作 | §7 のチェック |
| **R 再読み込み後の維持** | 取得状態を変えた後、ブラウザの再読み込み。さらに「設定」→ ログアウト → 再ログイン | 取得状態・件数・%がそのまま残る |

そのほか見ていただきたい点（任意）:
- ⓘ ボタン: 商品の詳細シート（大きな画像・概要・取得ボタン・編集）が下から出る
- 「Sample 大量テスト」: 120商品を上下にスクロールしても重くないか、画像がスクロールに合わせて読み込まれるか
- 他人のデータが見えないこと: 別の `@example.test` アカウントでログインし、Sample Live 2026 の URL を直接開くと「ページが見つかりません」になる
